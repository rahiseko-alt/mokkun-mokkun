# 階層型UIモック構成ツール (UI Mock Tree)

非エンジニアと開発者のUI認識齟齬を減らすための、階層型UIモック作成ツールです。

## 概要

- **目的**: 非エンジニアが「ページ構成・階層・画面遷移・ボタン名称・画面内の大まかな領域配置・参考画像配置・ページ単位コメント」を短時間で作成し、一意の識別子（例: `B-竹-地`）で会話できるようにするツール。
- **コア原則**:
  - 人間が読める階層識別子（例: `A`, `A-松`, `B-竹-地`）
  - 内部ID（UUID）、人間向け識別子、表示名の完全分離
  - 白い画面に四角（自動薄色割当）・画像・ボタンのみ配置するシンプル設計
  - ボタンから子ページを簡単作成＆直感的な画面遷移
  - 最大3世代の構成保存・復元（Git用語不使用）

---

## 起動方法

```bash
# 依存関係のインストール
npm install

# 開発サーバーの起動 (ローカルUIの表示)
npm run dev

# 受入テスト & ユニットテストの実行
npm test

# プロダクションビルド
npm run build
```

## 受入テスト結果

仕様書（Version 0.1）に定められた **受入テスト（T-001 〜 T-025）** および **破壊系テスト（T-101 〜 T-106）**、UI結合テストを含む全36テストを Vitest にて自動化・パスしています。

- **T-001**: プロジェクト作成時の初期識別子割当 (`A`)
- **T-002 〜 T-004**: 四角の自動薄色割当（赤・青・黄...）と色名称バッジ表示、ページごとの独立色順
- **T-005**: 画像配置と縦横比維持
- **T-006 〜 T-007**: ボタン配置とボタン名変更（内部ID・遷移先の独立）
- **T-008 〜 T-009**: ボタンから子ページ作成ダイアログ＆自動遷移、設定済みボタンの即時遷移
- **T-010 〜 T-012**: 識別子重複防止、識別子不足時の設定誘導、識別子変更時の既存パス再計算（内部ID不変）
- **T-013**: コメントの debounce 自動保存
- **T-014 〜 T-018**: ページ削除時の子孫全件確認リストアップ、外部参照ボタンリンク解除、最後の1ページ削除防止
- **T-019 〜 T-023**: 構成保存（日時タグ付き）、最大3件保持（4件目で最古削除）、確認ダイアログ付き復元
- **T-024**: LocalStorage による通常編集の自動保存・リロード復元
- **T-025**: ボタン名と識別子・遷移先の完全な独立性
- **T-101 〜 T-106**: 10階層以上の深さ、1000ページ規模の構造、100個の四角の色循環、大量画像、削除・復元時の整合性
